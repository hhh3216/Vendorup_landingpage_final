## 1. Hero — 멈추게 하기

### 메인 헤드라인 (확정)
> **카톡·문자로 온 주문, 오늘도 손으로 옮겨 치셨나요?**

### 서브 헤드라인
> 카톡·문자로 들어온 주문을 Vendor-UP이 읽고,
> **품목과 수량을 뽑아 우리 회사 품목코드에 맞춰 ERP에 올립니다.**
> **거래처는 하던 대로 주문하시면 됩니다.** 새로 깔 앱도, 배울 양식도 없습니다.

### CTA
- 1차(주 버튼): **`7일 무료로 시작하기`**
- 2차(보조 버튼): **`30초 만에 어떻게 되는지 보기`** → §6 라이브 데모 섹션으로 스크롤 앵커
- 버튼 하단 마이크로카피: `카드 등록 없이 시작 · 초기 파트너 10개사 마감 시 종료`

### 신뢰 배지 (버튼 아래 한 줄)
`거래처는 하던 대로 주문` · `초기 파트너 10개사 모집 중`

**[비주얼]**
- 좌측: 카톡 대화창 목업(실제 캡처 아님, 재현). 말풍선 예시 — `"내일 청상추 2박스, 대파 5단, 계란 15판 부탁드려요"` / `"오늘 어제꺼랑 똑같이요"`
- 우측: ERP 표가 **한 줄씩 자동으로 채워지는** 모션. 컬럼 = `품목코드 | 품목명 | 규격 | 수량 | 거래처`
- 가운데: 좌→우로 흐르는 얇은 라인. Vendor-UP 로고 지점에서 한 번 반짝
- 핵심: **"엉망인 입력 → 깔끔한 출력"** 대비가 3초 안에 읽혀야 함
- 사진·캡처 인식은 아직 미출시이므로 텍스트 말풍선만 사용

## 2. 문제 — 고통 묘사

### 섹션 헤드라인
> **주문 하나에 손이 몇 번 갑니까?**

### 리드 문장
> 읽고, 품목코드 찾고, 수량 옮겨 적고, ERP에 치고. 주문 한 건마다 이 과정을 사람이 반복합니다.
> 하루 수십, 수백 건이 쌓이면 문제는 여기서 시작됩니다.

### 페인포인트 3카드

| # | 헤드 | 본문 |
| --- | --- | --- |
| 1 | **끝없는 반복 입력** | 카톡을 열어 읽고, 우리 품목코드를 찾고, 수량을 옮겨 적고, ERP에 다시 칩니다. 주문 한 건에 같은 동작이 네다섯 번. 머리를 쓰는 일이 아니라 **손이 버티는 일**이 됩니다. |
| 2 | **오입력** | 같은 작업을 수백 번 반복하면 눈이 흐려집니다. 2박스가 20박스로, 5단이 15단으로 바뀝니다. 오입력은 담당자가 부주의해서가 아니라 **사람이 계속 옮겨 적기 때문에** 생깁니다. |
| 3 | **주문 누락** | 여러 거래처 주문이 한 채팅방, 한 문자함에 뒤섞여 있습니다. 손으로 하나씩 훑다 한 건을 놓치면, 다음 날 배송 사고와 클레임으로 돌아옵니다. |

### 섹션 마무리 한 줄
> 문제는 담당자가 아닙니다. **사람이 계속 옮겨 적어야 하는 구조**입니다.

**[비주얼]** 어두운 배경 / 카드 3개 그리드 / 각 카드 좌상단에 얇은 라인 아이콘. 감정 과장(우는 이모지 등) 금지, 담백하게. 1번 카드는 같은 동작이 반복되는 걸 시각화(동일 아이콘 4~5개 반복 배치)하면 메시지가 바로 읽힘.

## 3. 해결 — 변화 보여주기

### 섹션 헤드라인
> **받는 방식은 그대로, 입력만 사라집니다.**

### 🔑 강조 스트립 (섹션 최상단, 가장 크게)
> **거래처는 지금 하던 대로 주문하면 됩니다.**
> 앱을 새로 깔 필요도, 낯선 양식을 배울 필요도 없습니다. 바뀌는 건 우리 쪽 입력 과정뿐입니다.

> 📌 **왜 이걸 제일 크게 쓰나**: 도매 현장에서 새 시스템 도입이 엎어지는 가장 큰 이유가 "거래처한테 뭘 시켜야 하나"입니다. 여기에 해당이 없다는 건 이 서비스 최대 강점이므로, Hero·§3·§5 세 곳에서 반복 노출합니다.

### Before / After 표

| | 지금 | Vendor-UP 도입 후 |
| --- | --- | --- |
| 거래처가 주문하는 방식 | 카톡·문자 | 카톡·문자 **(그대로)** |
| 주문서 읽기 | 사람이 하나씩 확인 | AI가 자동으로 읽음 |
| 품목 매칭 | 담당자 기억에 의존 | 우리 회사 품목코드로 자동 매칭 |
| ERP 입력 | 한 건씩 손으로 타이핑 | 확인 후 자동 등록 |
| 반복 작업량 | 주문 건수만큼 그대로 | 확인 한 번으로 축소 |
| 오입력·누락 | 사고 난 뒤 수습 | 확신 낮은 건만 따로 표시해 사전 확인 |

> **Vendor-UP은 자체 수·발주 ERP를 제공하며, 기존에 쓰던 ERP를 대체하는 신규 도입입니다.** 도매업체를 다수 인터뷰한 결과 "기존 ERP엔 비정형주문 자동화가 없어서 아쉽다"는 의견이 많아, ERP까지 함께 만들었습니다.
> ⚠️ **대체 도입은 장벽이 큽니다.** "가입하면 끝"이 아니라 **데이터 이관·초기 세팅 지원이 핵심 온보딩**이 되어야 합니다 — §8 가치 스택의 "품목코드 초기 세팅 대행"·"데이터 반출 보장"을 부가 혜택이 아니라 **필수 온보딩 단계**로 승격 권장.

### 핵심 가치 3줄
1. **거래처는 하던 대로 카톡·문자만 보내면 됩니다.**
2. **읽고 찾고 치는 반복 작업이 사라집니다.** 담당자는 확인만 합니다.
3. **바뀌는 건 사이에 있던 '옮겨 적는 손'뿐입니다.**

**[비주얼]** 좌우 2단 슬라이더 또는 Before/After 토글. 스크롤 진입 시 After 컬럼이 순차적으로 채워지는 모션.

## 4. 작동 원리 — 5스텝

### 섹션 헤드라인
> **어떻게 되는 건가요?**

| STEP | 제목 | 설명 |
| --- | --- | --- |
| 01 | **받는다** | 카톡·문자로 들어온 주문 문장이 Vendor-UP으로 모입니다. 정해진 양식이 없어도 됩니다. |
| 02 | **추출한다** | 문장에서 품목, 규격, 수량, 납품일, 거래처를 AI가 뽑아냅니다. "어제랑 똑같이" 같은 말도 이전 주문 이력으로 해석합니다. ⚠️ 이력 참조 기능 구현 여부 확정 필요 |
| 03 | **맞춘다** | 거래처가 부르는 이름을 **우리 회사 품목코드**로 자동 변환합니다. 쓸수록 매칭 정확도가 올라갑니다. |
| 04 | **확인한다** | 정리된 주문이 화면에 뜹니다. 담당자가 훑어보고 승인하면 됩니다. 확신이 낮은 항목은 따로 표시됩니다. |
| 05 | **등록한다** | 승인 즉시 ERP에 반영됩니다. |

> ※ v3 변경: 구 버전의 "🛡 담당자 확인이라는 마지막 방어막" 강조 콜아웃은 삭제했습니다. 승인 단계는 위 STEP 04 안에서만 담백하게 서술하고, 별도로 크게 띄우지 않습니다.

## 5. 주문 접수 방식 — 두 가지 중 편한 쪽으로

### 섹션 헤드라인
> **주문은 어떻게 저희 쪽으로 들어오나요?**

### 리드
> 두 가지 방식을 모두 제공합니다. 업체 사정에 맞는 쪽을 고르시면 됩니다.
> **어느 쪽을 고르셔도 거래처는 지금 하던 그대로 카톡·문자로 주문하면 됩니다.**

#### 방식 1 — 거래처가 Vendor-UP 채널로 보내는 방식
거래처가 평소처럼 카톡·문자로 주문을 보냅니다. 보내는 곳에 Vendor-UP 채널 하나만 추가하면 되고, 나머지는 똑같습니다. Vendor-UP이 내용을 정리해 올려드리면 확인만 하시면 됩니다.

> 거래처 주문(카톡·문자) → Vendor-UP 채널 수신 → AI 추출·품목코드 매칭 → 담당자 확인 → ERP 등록

- **이런 업체에 맞습니다**: 주문량이 많아 담당자가 채팅방을 계속 들여다보기 어려운 곳
- **거래처가 하는 일**: 카톡에 채널 하나 추가. 그 외 달라지는 것 없음

#### 방식 2 — 받은 주문을 그대로 옮겨 붙이는 방식
지금처럼 우리 카톡·문자로 주문을 받고, 받은 내용을 Vendor-UP 창에 그대로 복사해 붙여넣습니다. AI가 정형화된 주문으로 만들어드립니다.

> 거래처 주문(카톡·문자, 우리가 직접 수신) → Vendor-UP에 복붙 → AI 추출·품목코드 매칭 → 담당자 확인 → ERP 등록

- **이런 업체에 맞습니다**: 거래처와의 채팅방을 그대로 유지하고 싶은 곳
- **거래처가 하는 일**: 없음. 번호도 방식도 그대로

#### 공통
두 방식 모두 **거래처에게 새로운 걸 요구하지 않습니다.** 차이는 "누가 Vendor-UP에 원문을 전달하느냐"뿐입니다.

### ⚠️ 표 레퍼런스 삽입 자리
> 형호님이 주시기로 한 **표 레퍼런스**를 이 자리에 참고자료로 넣습니다. 파일 받는 대로 여기에 삽입하고, 두 방식 비교표 디자인을 그 레퍼런스 구조에 맞춰 정리하겠습니다.
> (현재는 위 "방식 1 / 방식 2" 를 좌우 2열 비교표로 잡아둔 상태 — 행 항목: `거래처가 보내는 곳` / `거래처가 해야 할 일` / `우리가 해야 할 일` / `추천 대상`)

**[비주얼]** 두 흐름을 나란히 놓은 플로우차트 2개(각 4~5단계 아이콘 + 화살표) — **정지 이미지로만 제작.** 두 카드 모두 동등한 크기·비중으로 배치(어느 쪽도 "보조 옵션"처럼 보이지 않게). §6 라이브 데모에서 각각 체험 연결.

## 9. FAQ

> **궁금하실 것 같아서**

1. **거래처도 뭔가 새로 설치해야 하나요?**
   아니요. 거래처는 지금 하던 그대로 카톡·문자로 주문을 보내면 됩니다. 앱을 깔거나 새 양식을 배울 필요가 없습니다. (방식 1을 택하시면 거래처가 카톡에 채널 하나를 추가하는 정도이고, 방식 2를 택하시면 그것조차 없습니다.)

2. **ERP는 어떻게 되나요? 기존에 쓰던 ERP를 계속 써야 하나요?**
   Vendor-UP은 자체 수·발주 ERP를 제공하며, 기존에 쓰시던 ERP를 대체하는 형태로 도입됩니다. 비정형주문 자동화가 처음부터 그 안에 들어 있습니다. 기존 ERP에 있던 데이터는 초기 세팅 과정에서 이관을 도와드립니다. ⚠️ 이관 범위(품목코드/거래처/과거 주문 이력 중 어디까지) 확인 필요

3. **AI가 잘못 읽으면 어떡하죠?**
   정리된 주문은 담당자 확인 화면을 먼저 거칩니다. 확신이 낮은 항목은 따로 표시되어 눈에 띄게 보여드리고, 그 자리에서 바로 고칠 수 있습니다.

4. **품목 이름을 거래처마다 다르게 부르는데요.**
   거래처별 호칭을 우리 회사 품목코드에 한 번 연결해두면, 이후로는 알아서 매칭합니다. 쓸수록 정확해집니다.

5. **사진이나 캡처, 전화로 온 주문도 처리되나요?**

6. **주문 데이터가 밖으로 새지 않나요?**
   거래처·단가 정보는 업체의 핵심 자산입니다. **Vendor-UP에 들어온 데이터는 외부로 제공되지 않으며, 외부 AI 학습에 사용되지 않습니다.** 상세 보안 정책(암호화 방식, 저장 위치, 접근 권한)은 곧 별도 페이지로 공개합니다.

## 12. 스크롤 애니메이션 노트 (Claude Code 단계 전용 — 시안 단계에서는 읽기만)

토스(https://toss.im/) 참고 — **화면 전체가 넘어가는 방식이 아니라, 좌측 요소는 고정되고 우측 콘텐츠만 스텝별로 교체되는 방식**.

- 적용 구간: **§4 작동 원리(필수, 5스텝)**, §3 Before/After(선택)
- §6 라이브 데모는 스크롤 트리거가 아니라 **사용자 입력 기반 인터랙션**이므로 별도 로직 필요
- 구현 방향: `position: sticky` + 스크롤 진행도에 따른 스텝 인덱스 전환. **스크롤 하이재킹 금지** — 모바일 이탈 요인
- 모바일: sticky 해제하고 세로 카드 나열로 폴백
- 접근성: `prefers-reduced-motion` 존중, 애니메이션 없이도 내용이 전부 읽혀야 함

### 토스 톤앤매너 — 실제 캡처 기준 확인된 특징

**타이포 & 카피**
- 섹션당 메시지 하나. 흑색·굵은 대형 헤드라인 1~2줄 + 위/아래에 작은 라벨이나 회색 보조문장
- 헤드라인 안 핵심 단어를 **알약(pill) 뱃지로 인라인 강조**. Vendor-UP 응용: "주문은 `카톡` `문자`로, 입력은 `자동`으로"
- B2B 페이지는 상단에 회색 작은 라벨 후 큰 헤드라인 — "Vendor-UP for 도매업체" 활용 가능

**레이아웃**
- 좌측 끝에 **얇은 세로 tick 스크롤 진행 인디케이터** (§4 sticky 구간에 적용하기 좋음)
- 히어로 좌측에 **얇은 구분선으로 나뉜 기능 리스트** — §5(접수 방식)나 §7(로드맵) 요약 리스트에 응용 가능
- 우측엔 실제 UI가 떠 있는 **디바이스 목업**, 카드 레이어드 구성

**섹션 전환**

- 카드 아래 캡션은 **굵은 흑색 한 줄 + 회색 보조 한 줄** 2단 구조
